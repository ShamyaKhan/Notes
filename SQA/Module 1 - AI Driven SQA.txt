What is Software Quality Assurance?
-> a planned, systematic set of activities that ensure software meets defined quality standards
-> focuses on the process used to build software, not just the final product
-> goal is to prevent defect before they happen, not just catch them at the end
-> applies across the entire life-cycle, from requirements to production support


Quality: Meeting customer expectations
Assurance: Preventing defects/bugs


Why Software Quality Matters?
-> Trust & Reputation: a single major bug (payment failure) can break years of customer trust in minutes
-> Revenue Protection: downtime and bugs in ecommerce or banking apps directly translate into lost revenue
-> Security & Compliance: regulated industries (banking, healthcare) face legal penalties for quality failures
-> User Retention: poor quality is the first reason users abandon an app after one bad experience
-> Long-Term Cost: quality debt compounds: a quick and dirty release today is expensive to fix later


SQA in SDLC:
-> Requirements: QA reviews requirements for ambiguity, testability and completeness before coding starts
-> Design: QA validates architectures and UX decisions against non-functional needs like performance and security
-> Development: unit tests, code reviews and static analysis catch defects while code is still being written
-> Testing: functional, regression, integration and API testing validate the system as a whole
-> Deployment: smoke test and deployment checks confirm the release is safe to go live
-> Maintenance: production monitoring and regression testing protect quality as the system evolves


QA vs QC vs Testing:

     Aspect                         Quality Assurance                     Quality Control                       Testing
---------------------        ----------------------------------     ---------------------------------    -------------------------------
   Focus			Process oriented 		       Product oriented                    Execution oriented
   Goal				Prevent defects			       Identify defects			 Find bugs & verify behavior
   Approach			Proactive				Reactive				Reactive
 Activities	   Audits, standards, process reviews     Inspection, reviews of the product    Test case execution, exploratory testing
Responsibility 			Entire team			        QA/QC team                    Testers / Automation engineers
Example           Defining a code review checklist    Reviewing a build against the checklist    Running login test cases on that build





Objectives of Software Quality Assurance:
-> Prevent Defects: catch issues at the earliest possible point through reviews, standards and static analysis
-> Improve Customer Satisfaction: deliver software that is reliable, usable, and meets real user needs
-> Reduce Development Cost: avoid the exponential cost of late-stage fixes and emergency patches
-> Risk Reduction: identify and mitigate business, security and operational risks before release
-> Process Improvement: feed defect and quality data back into the team process for continuous improvement
-> Compliance: meet regulatory, legal and industry standards, critical in banking and fin-tech



Understanding Quality Models:
-> McCall's Quality Factors (1977):
  - one of the earliest formal quality models, grouped into three categories
  - product operation, product revision, product transition
  - introduced classic factors like reliability, efficiency and usability
  - still referenced today as the foundation modern standards were built on
-> ISO/IEC 25010 (Modern Standards):
  - the current international standard for software product quality (SQuaRE series)
  - defines 8 core characteristics: functional sustainability, performance efficiency, compatibility, usability, 
    reliability, security, maintainability, portability
  - used today for defining measurable, testable non-functional requirements 



How AI is Reshaping Software Testing:
-> From scripted to intelligent: traditional automation follows fixed scripts. AI driven testing understands intent, 
   adapts to change, and learns from past runs
-> AI across SDLC: AI now assists in requirement analysis, test case generation, code review, execution and defect triage
-> Self-healing automation: when a locator breaks due to UI changes, AI automatically finds the new element and updates the 
   test, reducing maintenance
-> Intelligent reporting: AI summarizes failures, clusters similar defects, and highlights root causes instead of raw
   pass/fail logs



AI Powered Testing Tools:
-> Claud Code, GitHub Copilot, Gemini, ChatGPT
-> used across the SDLC for requirement analysis, test case generation, code review and defect triage 



SQA in Agile:
-> Scrum and Sprint: Scrum is an agile framework organizing work into short, time-boxed sprints (usually 1-2 weeks)
   with regular delivery
-> User Story: a short plain-language description of a feature from the user's perspective e.g.("As a customer, I want 
   to reset my password")
-> Acceptance Criteria: The specific, testable conditions a user story must meet to be considered complete. QA's primary
   source for test case design
-> Definition of Done (Dod): A shared team checklist (coded, tested, reviewed, documented) confirming a story is truly 
   finished, not just coded
