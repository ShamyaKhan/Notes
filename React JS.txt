useEffect:
-> function passed into useEffect always gets called after initial render of after the DOM is updated
-> on the following renders, that function might be called depending on the dependency array
-> if we don't put a dependency array, the function will be called after every render
-> if there are some variables inside dependency array, the function will be called whenever that value of variables changes
-> we cannot use async await inside the function we pass into
-> the function we pass into useEffect, we are only allowed to return another function, known as cleanup 
-> react will hold onto the cleanup function for you and call automatically at some point of time in future
-> it gets called immediately after second render, just before running the useEffect again
-> then react creates a brand new cleanup function
-> it keeps going on like this
-> the cleanup function is only called if your arrow function is about to be called again
-> undo something before our next useEffect runs
-> common when we are watching for events manually on certain elements that are being rendered inside the DOM
-> commonly used with modal window or dropdown

Context:
-> a communication channel but redux is all about organization of data
-> data can be shared across all components
-> a component can reach out to context and ask for a specific piece of data
-> create context - returns a context object
-> it has two properties: provider and consumer. both are react components
-> provider: component used to specify what data we want to share
-> consumer: component used to get access to data
-> <BookContext.Provider value={}> <MyComponent /> </BookContext.Provider>
-> value prop contains data that will be shared
-> the components that need to have access this value, we have to put them in between the provider
-> the custom provider shows the built-in provider
-> <Provider>App</Provider>
-> the App component will show up as a prop to the provider called children

-> useCallback:

Events and State Design Process:
(I) what states and event handlers are there?
  - list out what a user will do and changes they will see while using your app
  - categorize each step as state or event handler
  - group common steps, remove duplicates, rewrite descriptions
(II) what name and type?
  - look at mockup, remove or simplify parts that aren't changing
  - replace remaining elements with text descriptions
  - repeat #4 and #5 with a different variation
  - imagine you have to write a function that returns the text of steps #5 and #6. in addition to your component props,
    what other arguments would you need?
(III) where is it defined?
  - decide where each event handler and state will be defined
  - does any component besides accordion reasonably need to know which item is expanded?
  - if other component needs to know that state, define in the lowest common parent
  - otherwise, define in the component only where it is needed
  - event handler should be usually defined in the same component as the state it modifies

Delayed State Update:
-> react: oh you want to update state...yeah I'll get around to it in the future
-> react does not process state updates instantly
-> the delay is known as batching
-> react allowing us to make several updates and it will process all those updates at the same time to improve performance

  - (I) get react to process state updates instantly (not ideal, app gets slower)
  - (II) get access to the most up-to-date value of state (functional update)
  - use functional update whenever our new update depends on the old value of state (conditional update)

How to implement click event handler outside the dropdown area so that it closes the dropdown?
(I) In plain JS:
  - document-wide click handlers
  - event capturing/bubbling
      - when an event occurs, browser wants to find event handlers to call
      - order in which search occurs is divided into three phases: capture, target, bibble
  - checking element inclusion
(II) In react:
  - useEffect
  - useRef

Capture Phase:
-> go to the far most parent of the clicked element, see if it has handlers. go to the second far most parent until the element 
   that was clicked/interated with (excluding that element)
-> if it finds the event handler, call it
-> frequently disabled

Target Phase:
-> go to the clicked/interacted element, check to see if it has event handlers
-> if so, it will be called

Bubble Phase:
-> go to the immediate parent and see if it has event handlers
-> then go the parent of the parent and see if it has event handlers

-> document.addEventListener('click', handleClick)
-> if we set event handlers with two arguments, then we will only for event handlers in target phase and bubble phase
-> document.addEventListener('click', handleClick, true)
-> it will look for event hanlders in capture phase and target phase
-> 90% of the time, we want it false
-> false by default


useRef:
-> allows a component to get a reference to a DOM it creates
-> 95% of the time used with DOM elements but can hold a reference to any value
-> it gives us an object with current property that holds the reference
