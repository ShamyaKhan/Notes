useEffect:
-> function passed into useEffect always gets called after initial render of after the DOM is updated
-> on the following renders, that function might be called depending on the dependency array
-> if we don't put a dependency array, the function will be called after every render
-> if there are some variables inside dependency array, the function will be called whenever that value of variables changes
-> we cannot use async await inside the function we pass into
-> the function we pass into useEffect, we are only allowed to return another function, known as cleanup 
-> react will hold onto the cleanup function for you and call automatically at some point of time in future
-> it gets called immediately after second render, just before running the useEffect again
-> then react creates a brand new cleanup function
-> it keeps going on like this
-> the cleanup function is only called if your arrow function is about to be called again
-> undo something before our next useEffect runs
-> common when we are watching for events manually on certain elements that are being rendered inside the DOM
-> commonly used with modal window or dropdown

How to implement click event handler outside the dropdown area so that it closes the dropdown?
(I) In plain JS:
  - document-wide click handlers
  - event capturing/bubbling
      - when an event occurs, browser wants to find event handlers to call
      - order in which search occurs is divided into three phases: capture, target, bibble
  - checking element inclusion
(II) In react:
  - useEffect
  - useRef

Capture Phase:
-> go to the far most parent of the clicked element, see if it has handlers. go to the second far most parent until the element 
   that was clicked/interated with (excluding that element)
-> if it finds the event handler, call it
-> frequently disabled

Target Phase:
-> go to the clicked/interacted element, check to see if it has event handlers
-> if so, it will be called

Bubble Phase:
-> go to the immediate parent and see if it has event handlers
-> then go the parent of the parent and see if it has event handlers

-> document.addEventListener('click', handleClick)
-> if we set event handlers with two arguments, then we will only for event handlers in target phase and bubble phase
-> document.addEventListener('click', handleClick, true)
-> it will look for event hanlders in capture phase and target phase
-> 90% of the time, we want it false
-> false by default


Why do we need Capture phase to implement Dropdown?
-> react does not re-render instantly, there is some gap of time
-> but it takes even longer for the entire bubble phase to be processed
-> by enabling capture phase, the custom event handler will be executed before react re-renders
-> because capture phase starts looking for event handlers from the furthest parent element
-> body - div [custom click event handler running here] [capture phase] 
-> option div [react click event handler running here] [target phase] 
-> div - body [bubble phase]

How Navigation Works in React:
-> User types our address in
  - always send the index.html file
  - when app loads up, look at the address bar and use it to decide what content to show
-> User clicks a link or presses the back or forward button:
  - stop the browser's default page switching behavior
  - figure out where the user was trying to go
  - update content on the screen and address bar to trick the user into thinking they swapped pages
 

Initial Render:
-> send index.html regardless of what address they are trying to access
-> html file will have a script tag inside that tells the browser to make a second request and get the bundle.js file
-> once the browser gets that file, the react application will be executed and start up
-> the react app will look at the address bar as soon as possible
-> it will look at the route portion of the address and apply a series of routing rules 
-> display the appropriate component according to the routes

User is already at our page and clicks some link/button:
-> intercept the navigation event and prevent browser from doing typical navigation process
-> handle navigation ourselves using JS code inside of the react app
-> take a look at where the user was trying to go to
-> update the address bar so that they think they navigated
-> apply routing rules once again - display the appropriate component according to the routes

Benefits of navigation in this way:
-> we are not resetting our javascript environment
-> when a user goes back to component they saw previously, we can show data that we already fetched instantly 
   without making another request to outside api
-> only works if the state is not defined inside the component because by default when a component is removed
   from the screen, all it's states gets dumped
-> if we store inside of parent component or a context object, it would be persisted

Handling back/forward button:
-> window emits a 'popstate' event if the current url was added by pushState method instead of manual typing
-> clicking on back/forward button will not cause a refresh if the current address I'm at was added with pushState
-> browser keeps track of history using stack
-> to detect a user going back/forward we will use popstate event
-> the only reason we have the state currentPath, setCurrentPath is to cause a re-render when user clicks back/forward button
